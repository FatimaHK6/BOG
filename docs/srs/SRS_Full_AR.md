## 1. مقدمة

### 1.1 نظرة عامة على الوثيقة

يهدف المشروع لتحديث نظام إدارة الدعاوى الحالي بديوان المظالم من أجل:
- استبدال النظام بالتقنيات المعاصرة برمجياً (استبدال Oracle Web Forms بـ OutSystems)
- تحسين تجربة المستخدم على النظام

تحتوي هذه الوثيقة على جميع متطلبات العمل الخاصة بنظام إدارة الدعاوى.

### 1.2 الافتراضات

- جميع الشاشات الواردة في الوثيقة هي بهدف التوضيح والاستدلال
- المرجع في الحقول وأنواعها هو نموذج البيانات في كل حالة استخدام
- الهيكلة الوظيفية للنظام ومخطط حالات الاستخدام عبارة عن تقريب للنظام

### 1.3 المصطلحات المستخدمة

| الاختصار | الوصف |
|----------|-------|
| BR | قاعدة عمل (Business Rule) |
| UC | حالة استخدام (Use Case) |
| FR | متطلب وظيفي (Functional Requirement) |
| BOG | ديوان المظالم (Board of Grievances) |
| ALT | مسار بديل (Alternative Path) |
| BC | قيد عمل (Business Constraint) |
| INF | رسالة معلومات (Information Message) |
| CON | رسالة تأكيد (Confirmation Message) |
| ERR | رسالة خطأ (Error Message) |
| NTF | إشعار (Notification) |

## 2. عن النظام

### 2.1 وحدات النظام

النظام يتكون من الوحدات التالية:
- القيد
- الإحالة
- المحاضر
- الأحكام
- الاستعلامات
- التقارير
- الإعدادات العامة
- إدارة المستخدمين

### 2.2 الحلول المرغوب الوصول إليها

- تجديد نظام إدارة الدعاوى الحالي بديوان المظالم
- استبدال النظام بالتقنيات المعاصرة
- تحسين تجربة المستخدم على النظام

### 6.5 حالات الاستخدام

#### 6.5.1 إدارة طلبات قيد دعوى إدارية

##### 6.5.1.1 إضافة طلب قيد دعوى من داخل المحكمة

**حالة الاستخدام:** إضافة طلب قيد دعوى إدارية جديد من داخل المحكمة

**المستخدمين:**
- موظفو القيد بالمحاكم الإدارية
- إدارة النظام

**الشروط الاستباقية:**
- تسجيل دخول المستخدم للنظام
- المستخدم محدّد القسم مسبقاً في حال وجود أكثر من قسم للمستخدم

**المسار الرئيسي:**
1. يقوم المستخدم بتعبئة نموذج بيانات الدعوى الأساسية
2. يقوم المستخدم باختيار **إنهاء الطلب**
3. يقوم النظام بحفظ كافة تفاصيل بيانات طلب قيد الدعوى
4. يقوم النظام بحفظ حالة **مسوّدة** للطلب
5. يقوم النظام بتنفيذ حالة الاستخدام **اتخاذ إجراء على طلب قيد دعوى**

**المسارات البديلة:**

| الرمز | الوصف |
|-------|-------|
| ALT01 | عند اختيار **حفظ كمسوّدة**: حفظ البيانات والرجوع للخطوة 1 |
| ALT02 | عند اختيار **إلغاء**: عرض رسالة تأكيد CON01 والخروج |
| ALT03 | عند اختيار **المدعّين**: تنفيذ حالة الاستخدام المدعين |
| ALT04 | عند اختيار **المدعّى عليهم**: تنفيذ حالة الاستخدام المدعى عليهم |
| ALT05 | عند اختيار **معلومات إضافية**: تنفيذ حالة الاستخدام معلومات إضافية |
| ALT06 | عند اختيار **مرفقات الطلب**: تنفيذ حالة الاستخدام مرفقات طلب قيد دعوى |

**قواعد العمل:**

| الرمز | القاعدة |
|-------|---------|
| BC01 | يتم حفظ بيانات طلب الدعوى بكافة تفاصيله في بوابة معين الخارجية |
| BC02 | يتم حفظ إجراء تغيير حالة الطلب فقط إذا كان الطلب بدون حالة |
| BC03 | خيارات استكمال النواقص تظهر وفقاً لمصفوفة الحالات |
| BC04 | خيار **إنهاء الطلب** يظهر في حال أن الطلب بدون حالة أو أي حالة تسمح بالانتقال |
| BC05 | خيار **استعراض النواقص** يظهر في حال إضافة نواقص على الطلب |

**بيانات الدعوى الأساسية:**

##### 6.5.1.1.1 المدعين (قائمة المدعين)

**حالة الاستخدام:** عرض قائمة المدعين المسجلين على طلب قيد الدعوى

**الشروط الاستباقية:**
- تسجيل دخول المستخدم للنظام
- المحكمة التي ينتمي لها قسم المستخدم هي نفس المحكمة المقدّم لديها طلب قيد الدعوى

**المسار الرئيسي:**
1. يقوم النظام بعرض نموذج بيانات المدّعين

**المسارات البديلة:**

| الرمز | الوصف |
|-------|-------|
| ALT01 | عند اختيار **إضافة مدعّي**: تنفيذ حالة الاستخدام إضافة مدعّي |
| ALT02 | عند تحديد مدّعي واختيار **تفاصيل**: تنفيذ استعراض تفاصيل مدّعي |
| ALT03 | عند تحديد مدّعي واختيار **تعديل**: تنفيذ تعديل مدعّي |
| ALT04 | عند تحديد مدّعي واختيار **العنوان المختار**: تنفيذ العنوان المختار للمدعّي |
| ALT05 | عند تحديد مدّعي واختيار **المرفقات**: تنفيذ مرفقات مدعّي |
| ALT06 | عند تحديد مدّعي واختيار **إضافة ممثّل**: تنفيذ إضافة ممثل لمدّعي |
| ALT09 | عند تحديد مدّعي واختيار **تحديد كمقدّم طلب**: عرض CON05 ثم تحديد |
| ALT10 | عند تحديد مدّعي واختيار **حذف**: عرض CON07 ثم حذف المدّعي |

**قواعد العمل:**

| الرمز | القاعدة |
|-------|---------|
| BC01 | الخيارات (إضافة، حذف، تحديد كمقدّم طلب) تظهر في حالات: لا يوجد حالة / مسوّدة / استكمال النواقص |
| BC02 | الخيارات (تعديل) تظهر في حالات: لا يوجد حالة / مسوّدة |
| BC03 | خيار العنوان المختار يظهر إذا اختلفت مدينة المدّعي عن مدينة المحكمة |
| BC04 | النظام يحتوي على إعدادات بأنواع المرفقات الممكن رفعها بحسب نوع المدّعي |
| BC05 | خيار المرفقات يظهر فقط إذا كان هناك قائمة غير فارغة بأنواع الملفات |
| BC06 | في حال وجود مرفقات إجبارية ومستوفاة يتم إسناد "المرفقات مستوفاة" لحالة المرفقات |
| BC07 | خيار تحديد كمقدّم طلب يظهر فقط إذا كان نوع المدّعي **فرد** |
| BC08 | عند تحديد مدعى كمقدم للطلب وكان موجود في قائمة الممثلين يتم اعتباره أيضاً كمقدم للطلب |

**النماذج والحقول:**

| حالة المرفقات | عرض | لا |

##### 6.5.1.1.2 إضافة مدعي

**حالة الاستخدام:** إضافة مدعي جديد على طلب قيد الدعوى

**الشروط الاستباقية:**
- الطّلب مقدّم من داخل المحكمة وحالته (لا يوجد حالة / مسوّدة / استكمال النواقص)

**المسار الرئيسي:**
1. يقوم المستخدم باختيار نوع المدعّي المراد إضافته
2. يقوم النظام بعرض نموذج البيانات المقابل لنوع المدّعي
3. يقوم المستخدم بتعبئة نموذج بيانات المدعّي
4. يقوم المستخدم باختيار حفظ ليقوم النظام بحفظ بيانات المدّعي

**قواعد العمل:**

| الرمز | القاعدة |
|-------|---------|
| BC01 | يتم عرض نموذج البيانات المقابل لنوع المدّعي المختار وإخفاء النماذج الأخرى |
| BC02 | **التكامل مع أبشر**: في نموذج بيانات فرد وفي حال أن نوع الفرد مواطن أو مقيم وبعد إدخال رقم الهوية يتم استدعاء خدمة التحقق. في حال تفعيل التكامل مع أبشر تصبح الحقول التالية غير قابلة للتعديل: (نوع الهوية، رقم الهوية، تاريخ الميلاد، الاسم الأول، اسم الأب، اسم الجد، اسم الفخذ، اسم العائلة، تاريخ إصدار الهوية، تاريخ انتهاء الهوية) |

**الاستثناءات:**

| الرمز | الوصف |
|-------|-------|
| ERR011 | في حال إضافة مدّعي جديد موجود مسبقاً بالطلب بنفس رقم الهوية وبنفس نوع المدّعي |
| ERR014 | في حال إرجاع خطأ من خدمة التحقق عن رقم هوية |
| ERR015 | في حال إرجاع خطأ من خدمة التحقق عن رقم هوية |

##### 6.5.1.1.4 تعديل مدّعي

**حالة الاستخدام:** تعديل بيانات مدّعي مسجل على طلب قيد الدعوى

**الشروط الاستباقية:**
- الطّلب مقدّم من داخل المحكمة وحالته (لا يوجد حالة / مسوّدة)

**المسار الرئيسي:**
1. يقوم النظام بعرض نموذج بيانات المدعّي
2. يقوم المستخدم بتعديل قيم حقول نموذج بيانات المدعّي
3. يقوم المستخدم باختيار حفظ ليقوم النظام بحفظ بيانات المدّعي

**قواعد العمل:**

| الرمز | القاعدة |
|-------|---------|
| BC01 | يتم عرض نموذج البيانات المقابل لنوع المدّعي المختار |
| BC02 | في حال أن نوع المدّعي **فرد** فإن الحقول (رقم الهوية، نوع الهوية) **غير قابلة للتعديل** |
| BC03 | في حال أن البيانات الشخصية تم جلبها عبر التكامل مع أبشر، تصبح الحقول التالية غير قابلة للتعديل |
| BC04 | خيار **استرجاع البيانات من أبشر** يظهر فقط في حال: نوع المدّعي فرد + نوع الهوية (هوية وطنية أو هوية مقيم) + البيانات لم تُجلب سابقاً من أبشر + التكامل مفعّل |
| BC05 | في حال أن نوع المدّعي **فرد بدون هوية** فإن الحقل (رقم الوثيقة) **غير قابل للتعديل** |

##### 6.5.1.1.5 مرفقات مدّعي

**حالة الاستخدام:** إدارة مرفقات المدّعي (إضافة، عرض، تعديل، حذف)

**المسار الرئيسي:**
1. يقوم النظام بعرض رسالة INF01 بأنواع المرفقات المطلوبة
2. يقوم المستخدم بعرض نموذج مرفقات مدعّي بالمرفقات المرفوعة
3. يقوم المستخدم باختيار إضافة مرفق جديد وتعبئة البيانات
4. يقوم المستخدم باختيار حفظ ليقوم النظام بحفظ بيانات المرفق
5. يقوم النظام بالرجوع للخطوة رقم (2)

**قواعد العمل:**

| الرمز | القاعدة |
|-------|---------|
| BC01 | لكل نوع مدّعي مجموعة من أنواع المرفقات الممكن رفعها (إعدادات بقاعدة البيانات) مع عدد المرفقات الأعلى لكل نوع (إجباري أو اختياري) |
| BC02 | يتم توليد رسالة INF01 بالتنسيق: `{رقم تسلسلي} {نوع المرفق} بحد أقصى {عدد}` |
| BC03 | خيارات (إضافة مرفق جديد، تعديل مرفق) تظهر في حالات: لا يوجد حالة / مسوّدة / طلب جديد / استكمال النواقص |
| BC04 | **الملف المرفق غير قابل للتعديل** عند تعديل بيانات مرفق (فقط الملاحظات ونوع المرفق) |

**النماذج والحقول:**

| اسم الحقل | تعديل/عرض | إجباري | قيود الحقل |
|-----------|-----------|--------|------------|
| ملاحظات على المرفق | تعديل | نعم | - |
| نوع المرفق | تعديل | نعم | اختيار وحيد من القيم الممكنة |
| المرفق | تعديل | نعم | **ملف PDF واحد فقط - أقصى حجم 4 ميجابايت** |

##### 6.5.1.1.6 العنوان المختار للمدّعي

**حالة الاستخدام:** إدارة العنوان المختار للمدّعي (في حال اختلاف مدينة المدّعي عن مدينة المحكمة)

**الشروط الاستباقية:**

| الرمز | القاعدة |
