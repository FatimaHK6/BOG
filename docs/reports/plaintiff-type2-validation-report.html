🟠 المشاكل الرئيسية (Major Issues)

MAJOR-001 حقول إضافية معروضة لا تنتمي لـ Type 2

الموقع: plaintiff-form.component.html

الحقول الزائدة:

  • نوع الهوية (Identity Type) - غير موجود في SRS 6.3.10
  • تاريخ إصدار الهوية - غير موجود في SRS 6.3.10
  • تاريخ انتهاء الهوية - غير موجود في SRS 6.3.10
  • حالة العمل - غير موجود في SRS 6.3.10
  • جهة العمل - غير موجود في SRS 6.3.10
  • المهنة - غير موجود في SRS 6.3.10

الحل: إخفاء هذه الحقول عندما يكون selectedPlaintiffType === 2

MAJOR-002 لا يوجد فحص تكرار لرقم الوثيقة

الموقع: PlaintiffBL.cs - CreateAsync method

الوصف: لا يوجد فحص ERR011 للتحقق من عدم وجود مدعي بنفس رقم الوثيقة

الحل:

// PlaintiffBL.cs - Add in CreateAsync method if (!string.IsNullOrEmpty(dto.DocumentNumber)) { var exists = await _plaintiffRepository .ExistsByDocumentNumberAsync(requestId, dto.DocumentNumber, dto.PlaintiffTypeId, cancellationToken); if (exists) throw new InvalidOperationException( "ERR011: المدّعي موجود مسبقاً بنفس رقم الوثيقة"); }

التوصيات

🔴 الأولوية الحرجة (يجب تنفيذها فوراً)

  1. تفعيل التحقق من عنوان السكن في Backend و Frontend
  2. إضافة فحص تكرار رقم الوثيقة (ERR011)

🟠 الأولوية الرئيسية

  1. إخفاء حقول نوع الهوية وتواريخ الهوية لـ Type 2
  2. إخفاء قسم بيانات العمل لـ Type 2
  3. إضافة تحقق صيغة البريد الإلكتروني
  4. إضافة MaxLength للحقول الاختيارية

قائمة الاختبار

اختبارات Backend

  • إنشاء Type 2 بجميع الحقول المطلوبة
  • إنشاء Type 2 بدون عنوان سكن (يجب أن يفشل)
  • إنشاء Type 2 برقم وثيقة مكرر (يجب أن يفشل)
  • اختبار حد رقم الوثيقة = 20 حرف
  • اختبار تحقق صيغة البريد الإلكتروني

اختبارات Frontend

  • اختيار Type 2 - التحقق من إخفاء حقل نوع الهوية
  • اختيار Type 2 - التحقق من إخفاء تواريخ الهوية
  • اختيار Type 2 - التحقق من إخفاء قسم بيانات العمل
  • اختيار Type 2 - التحقق من إخفاء زر أبشر
  • إرسال النموذج بدون عنوان سكن (يجب أن يفشل)
  • التحقق من أن عنوان الحقل يظهر "رقم الوثيقة"
  • التحقق من أن رقم الوثيقة للقراءة فقط بعد الإنشاء
